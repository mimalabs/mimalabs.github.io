# MIMA LABS — GitHub Pages release guide

Repository: https://github.com/mimalabs/mimalabs.github.io
Production domain (after cutover): https://www.mimalabsworld.com

This ZIP contains one TypeScript project, content, optimized covers, generated pages, tests, a GitHub Actions workflow and release instructions. **None of the stages happens automatically from downloading the ZIP.**

## Stage 1 — prepare source (current stage)

Run `npm ci` then `npm test`. Review `SEO_AND_DOMAIN_STAGE_1.md`. The canonical origin is a TypeScript constant in `src/build/config.ts`; CI no longer overwrites it with a separate `SITE_URL` variable. No custom domain or DNS setup occurs at this stage.

## Stage 2 — update repository (requires approval)

1. Confirm the old website has a recoverable commit and make a backup branch from its current `main`.
2. Unzip the new project into the repository root, preserving `.git/`, and review all additions/deletions. Do not commit `node_modules/` or temporary image-import folders.
3. Prefer a new branch such as `release/mima-v7-domain` and a pull request; use a descriptive commit: `feat(site): prepare multilingual MIMA LABS V7 and custom-domain SEO`.
4. **Do not merge or push to `main` yet:** the existing workflow deploys on every `main` push when Pages is configured for Actions. Stage 3 must verify the workflow and planned go-live sequence first.

## Stage 3 — configure GitHub Actions (requires separate approval)

1. Settings → Pages → Build and deployment → Source: **GitHub Actions**.
2. Inspect `.github/workflows/deploy-pages.yml`: Node 24, `npm ci`, `npm test`, Playwright Chromium, upload `site/`, deploy. Check permissions and run results.
3. Confirm generated canonical URLs, sitemap and robots against `www.mimalabsworld.com`.
4. Arrange the merge and domain change to minimize disruption. Merging into `main` may deploy the new site before the custom domain starts resolving.

## Stage 4 — bind and switch domain (requires separate approval)

1. In GitHub Settings → Pages, add custom domain **`www.mimalabsworld.com`** and verify ownership as prompted **before** changing registrar DNS.
2. At the DNS provider, change only the confirmed `www` CNAME to `mimalabs.github.io` (no `/` and no repository suffix). Preserve unrelated DNS records, especially email.
3. Verify HTTPS enforcement, English root, `/de/`, `/es/`, `/fr/`, `/it/`, `/ca/`, Back behavior, socials, Amazon links and mobile viewports.
4. Test the apex `mimalabsworld.com` separately; choose an optional redirect to `www` and follow GitHub's apex DNS instructions if desired.
5. Submit and monitor `https://www.mimalabsworld.com/sitemap.xml` in Google Search Console after the live cutover.

**Important:** With this custom GitHub Actions Pages build, GitHub ignores a repository `CNAME` file. The custom domain is registered in Pages settings; no `CNAME` file is generated by the TypeScript build.

## Review gates

The business owner approves wording, products and legal information; Architect reviews modularity and changed file scope; QA verifies no regressions; SEO Manager reviews metadata/canonical/hreflang/sitemap; Release Engineer confirms stage-specific evidence. If any mandatory check fails, **do not release**.

Product maintenance remains separate: use `PRODUCT_UPDATE_GUIDE.md` and replace covers with `npm run images:import` rather than editing generated HTML or CSS per book.
